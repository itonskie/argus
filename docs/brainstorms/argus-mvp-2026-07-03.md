# argus MVP

**Date:** 2026-07-03
**Grilled:** 2026-07-03
**Status:** PRD Created
**PRD:** https://github.com/itonskie/argus/issues/1

## Summary

argus is a keyboard-first TUI for inspecting and exercising Model Context Protocol (MCP) servers. The MVP is deliberately small: point it at a local MCP server, see what it exposes, fire off calls, confirm things work. That's the whole job.

Involves UI/frontend work (the entire app is a terminal UI built with Ink).

## Problem / Motivation

Building MCP servers today, devs either hand-roll JSON-RPC payloads to test them or use Anthropic's official web-based Inspector. The Inspector already covers connect / browse / invoke / view — argus does not compete with it on capability.

**argus's job is ergonomic parity for the terminal-native / vim-in-tmux audience.** The value prop is "the inspector I don't have to leave the terminal for," not "features the Inspector lacks." Success looks like the vim crowd reaching for argus instead of switching to a browser tab while iterating.

Implication: UX cannot be worse than the Inspector for shared features, and startup-to-first-paint must feel instant (otherwise the already-open browser tab wins).

## Proposed Approach

Three-pane TUI, vim-style navigation. Point it at a server, browse capabilities, invoke, see results. No recording, no replay, no diffing — just an inspector.

### Launch

```
argus ./path/to/server.js
```

The path is required. No bare `argus` — MVP has no saved-configs list.

### Layout

Three panes, left → right:

- **Left — Connection info.** The currently-connected server: path, transport, process status. No persistence, no list, no file format. If we later want saved configs we add them without breaking anything.
- **Middle — Capabilities.** Tabs for `t` (tools), `r` (resources), `p` (prompts). Each tab is a scrollable list of what the connected server exposes.
- **Right — Detail + form + results.** Highlighting an item in the middle pane shows its schema + description as a preview. Pressing Enter focuses the form (ajv-driven from the JSON Schema). Submitting fires the call; the response replaces the form in the same pane, pretty-printed and scrollable.

### Form engine — graceful ladder

Not "form works or falls back to raw JSON for the whole thing." A field-level ladder:

- **Real form fields for:** primitives (`string` / `number` / `boolean` / `enum`), nested objects, arrays of primitives.
- **Field-level raw JSON textarea fallback for:** arrays of objects, `oneOf` / `anyOf`, `$ref`, base64 / binary. The offending field renders as JSON; other fields in the same form stay as real inputs.
- **Ajv validates the assembled payload on submit** regardless of which fields used the fallback.

### Interactions

- Vim-style navigation between panes (`h`/`l` to move panes, `j`/`k` within lists).
- `t` / `r` / `p` switch capability tabs.
- Enter focuses form.
- Submit runs the call, response renders in right pane.
- For very large responses, `o` opens the raw payload in `$PAGER`.
- In-session history: arrow-up in the form re-runs the last call with the same args. Not persisted across sessions.

## Structure & Architecture

- **App shell** — Ink app, three-pane layout component, keyboard router.
- **MCP client wrapper** — thin layer over `@modelcontextprotocol/sdk` that manages the single active connection (connect / list capabilities / invoke / disconnect). **Lazy-loaded** — not imported until after Ink's first paint.
- **Form engine** — takes a JSON Schema, renders form fields per the graceful ladder above, validates via ajv, produces a request payload. **Ajv is lazy-loaded** — not imported until first form render.
- **Result view** — pretty-printer + `$PAGER` escape hatch for large payloads.
- **Test-server fixture** — a small in-repo MCP server exposing every supported schema shape (flat primitives, nested objects, arrays of primitives, plus one of each fallback case). Drives ajv and form-render tests.

### No disk state in MVP

Zero files under `~/.argus/`. No `servers.json`, no history file, no cache. When we later want saved configs or cross-session history, we add them as separate features without breaking anything.

### Startup budget

**Cold-start to first paint must be under 200ms** on a modern laptop. Enforced by:

- tsup single-file ESM bundle, minified.
- `@modelcontextprotocol/sdk` and `ajv` imported dynamically, after Ink's first render. The shell paints immediately; "connecting..." updates as the SDK finishes loading.
- No top-level imports of heavyweight deps anywhere in the main entry.

## Dependencies

Locked in the README and unchanged by this brainstorm:

- Node 20+ / TypeScript strict
- Ink (React for terminals)
- `@modelcontextprotocol/sdk` (official client)
- ajv (JSON Schema validation for the dynamic forms)
- tsup (bundling)
- Vitest + ink-testing-library (tests)
- Biome (lint + format)
- pnpm (package manager)

## Open Questions & Risks

- **Connection lifecycle for stdio.** The MCP SDK spawns a child process. Need to handle: server crashes mid-session, server that never responds to `initialize`, clean shutdown of the child on TUI exit. Standard stuff but easy to get wrong.
- **Ink + large output.** Rendering a 200KB response in Ink could be sluggish. The `$PAGER` escape hatch is the mitigation; we need to pick a size threshold at which we auto-suggest paging (e.g. > 20KB).
- **Startup budget enforcement.** 200ms is easy to blow with a stray top-level import. Worth adding a startup-timing check to CI so regressions are caught, not discovered post-ship.

## Out of Scope for MVP

- **Session recording / replay.** No `~/.argus/sessions/`. Regression testing lives in code, not in the TUI.
- **SSE / HTTP transports.** stdio only. Adds later without breaking anything.
- **Saved server configs.** Launch via path each time. Adds later without breaking anything.
- **Cross-session history.** In-session only.
- **Bookmarks / named saved calls.**
- **OAuth flows.**
- **Multi-server-at-once.**
- **Eval suites.**

## Definition of Done

- Works end-to-end (list → invoke → view result) against the in-repo test-server fixture.
- Manual smoke test against `@modelcontextprotocol/server-filesystem` passes before release.
- Cold-start to first paint measured at < 200ms on a modern laptop.
- CI green (lint, type-check, tests) on Node 20 + 22.
- Package publishes cleanly as `@itonskie/argus` and `npx @itonskie/argus <path>` works.

## Grill Resolutions

Decisions locked during the 2026-07-03 grill session:

- **Value prop framing.** argus doesn't compete with the official Inspector on features. It's ergonomic parity for the vim / tmux crowd. Success = "the vim crowd reaches for argus instead of switching to a browser tab." UX cannot be worse than the Inspector for shared features, and startup must feel instant.
- **Form engine as graceful ladder.** Ship real form fields for primitives, nested objects, and arrays of primitives. Field-level raw-JSON textarea fallback for arrays of objects, `oneOf`/`anyOf`, `$ref`, binary. Not a whole-form fallback — the escape hatch is per-field so users still get the form UX for the parts we handle.
- **DoD test strategy.** In-repo synthetic test-server fixture covers every supported schema shape and drives CI. Manual smoke test against `@modelcontextprotocol/server-filesystem` before releases. Real servers as unit tests were rejected (network deps + moving targets).
- **Cut: saved server configs.** Launch is always `argus <path>`. Left pane becomes connection info, not a persistent list. No `~/.argus/servers.json`. Adds later cleanly if needed.
- **Cut: persistent history.** In-session only. Arrow-up re-runs the last call within the current process; nothing persists.
- **No `~/.argus/` in MVP.** Zero disk state. Nothing to migrate later.
- **Startup budget < 200ms cold-to-first-paint.** Enforced via tsup single-file ESM bundle + lazy imports of `@modelcontextprotocol/sdk` and `ajv`. Added as an MVP acceptance criterion.
- **Ink stays.** The form engine alone justifies it; imperative TUI forms would be miserable. Latency mitigated by lazy loading, not by dropping Ink.
